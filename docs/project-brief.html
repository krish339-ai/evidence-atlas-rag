Evidence Atlas RAG

Ask across PDFs. Compare what the sources actually say. Follow each answer back to its evidence.

What the application does

The default sample covers selected CMS Medicare Advantage inpatient and outpatient prior authorization guidance. A secondary collection contains RAG, Self-RAG, and CRAG research papers. Users can upload text-based PDFs, choose documents, click suggested questions, inspect page citations, compare sources, build an excerpt matrix, and export the evidence trail.

Scope matters. A universal checklist for every payer exceeds the CMS sample and is deliberately refused. A generated answer that fails citation or evidence checks is withheld as Answer not verified, with retrieved passages preserved for inspection.

Architecture: local orchestration, explicit provider calls

The browser and Python application run locally. Live mode transmits text to the configured embedding and model providers. Demo mode uses lexical hash vectors and returns verbatim excerpts without an LLM. Remote tracing is disabled by the application.

Comparisons require coverage of selected documents. List items from different passages need separate citations. Local checks catch unknown IDs, recognizable omitted exceptions, and literal details absent from the cited passage. The semantic audit checks support and completeness, but can still be wrong; human source review remains necessary.

Suggested upload questions come from document headings and repeated terms. Clicking submits immediately. Completed questions clear; request errors preserve the draft. The reading matrix always contains source excerpts, not generated conclusions.

A refresh now reads the existing collection descriptor without re-embedding or upserting. If the backend has restarted or the collection has been cleared, the app reports that it cannot restore it; it does not switch silently to another document. Memory-backed collections use the same refresh mechanism. Closing a tab ends its saved selection.

The main live/memory session and isolated live/Pinecone test are separate. restart-live.bat selects live/memory; Pinecone requires the separate settings in PINECONE.md.

Evidence of progress—and its limits

The research set has ten answerable cases and four fallback cases; three of four fallback cases passed. Its recorded local query p95 was 193 ms, excluding ingestion. These figures do not measure live semantic retrieval, Pinecone performance, clinical validity, or generated-answer faithfulness.

A public four-page PDF produced twelve Pinecone chunks and a cited answer. Human review found an omitted payer exception despite audit approval. The captured omission now fails locally, and a bounded public live replay includes the exception. Browser refresh was verified with an existing nine-passage collection without reindexing.

Later list-answer checks exposed facts from multiple passages under one citation. Constrained IDs, per-item schema guidance and literal-detail checks address this failure. Captured faulty drafts fail offline; synthetic role and skill lists passed with separate citations. The final bounded private replay returned separately cited role and skill claims, reviewed for individual source support; list completeness remains a separate limitation. See the verification record for scope and limitations.

Iterations and lessons

  1. Hybrid ranking improved local research recall, but did not eliminate retrieval misses.
  2. Copying source quotes locally avoided model corruption of PDF punctuation. Assessing evidence before the audit verdict reduced an observed contradictory decision.
  3. Pinecone transport metadata must not mutate local source documents; copied inputs and authoritative evidence fields prevent collisions.
  4. Quotation and citation validity do not establish entailment. Explicit exceptions, dates, list items and factual scope require separate checks.
  5. Persistent vectors do not equal a persistent application session. Browser restoration and server durability are distinct features.

Remaining validation

Held-out claim support, false refusals, answer coverage, p50/p95 live latency, restart durability, and broader accessibility remain open. Local guards are conservative: valid paraphrases or new abbreviations may be rejected. The application is a local prototype, not a production authorization system.
